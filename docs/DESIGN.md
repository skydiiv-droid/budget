# 설계

## 왜 이 구조인가

아이폰은 다른 앱의 알림을 읽을 수 없다. `UNUserNotificationCenter`는 자기 앱
알림만 다루고, 안드로이드의 `NotificationListenerService`에 대응하는 API가 없다.
그래서 **현대카드 앱 푸시는 원천적으로 못 읽는다.** 문자를 트리거로 쓰는 이유다.

네이티브 앱(SwiftUI) 경로는 Xcode가 macOS 전용이라 접었다. Apps Script는
무료이고, 서버 유지가 없고, 로직이 전부 코드로 남아 버전 관리가 된다.

## 계정 · 거래 · 스케줄

### 카드도 "계정"이다

카드로 긁으면 카드 계정의 부채가 늘고, 결제일에 계좌 → 카드로 **이체**가 일어난다.
카드 대금 출금을 지출로 잡으면 매달 카드값만큼 지출이 두 배로 잡힌다.

거래 타입은 셋: `expense` / `income` / `transfer`.
`transfer`는 예산·통계에서 항상 제외된다. 적금 자동이체도 여기 들어간다.

### 두 개의 축

| | 기준 | 쓰임 |
|---|---|---|
| `Transaction.occurredAt` | 사용일 | "9월에 무엇을 샀나" — 소비 분석 |
| `PaymentSchedule.dueDate` | 결제 예정일 | "9월에 얼마가 나가나" — 현금흐름 |

거래 1건 → 청구 스케줄 N건.

| 결제 방식 | Transaction | PaymentSchedule |
|---|---|---|
| 일시불 30만 | 9/10 · 30만 | 10/5 · 30만 (1건) |
| 3개월 할부 | 9/10 · 30만 | 10/5·10만, 11/5·10만, 12/5·10만 |
| 리볼빙(약정 30%) | 9/10 · 30만 | 10/5 · 9만 + 이자, 잔액 21만은 11/5로 재생성 |

리볼빙 **이월 원금은 새 지출이 아니다.** 스케줄이 미래로 밀린 것뿐이라
이중계상이 나지 않는다. 새로 생기는 지출은 이자 하나(`kind: interest`)뿐이고,
카테고리 `금융비용`으로 잡힌다.

기본 보기는 **결제 기준**(할부를 월 분할로 보고 싶다는 요구에 맞춘 값).

## 잔액 앵커

문자에 찍힌 값과 앱 계산값을 대조해 누락을 자동으로 잡는다.

```
우리은행 문자의 잔액        vs  앱이 계산한 계좌 잔액
현대카드 문자의 월 누적     vs  앱이 계산한 이번 달 카드 사용 합계
```

사이클이 1일~말일이고 현대카드 누적도 월 기준이라 경계 보정이 필요 없다.

차액이 생기면 그 자리에서 "누락 의심"으로 뜬다. 자동화가 며칠 멈춰 있었는지를
월말까지 기다리지 않고 알 수 있다. 현금 사용분(문자가 안 오는 돈)도 차액으로 드러난다.

## 파서 3계층

| | 언제 동작 | 정확도 |
|---|---|---|
| Layer 1 제네릭 추출기 | 샘플 0개로 동작 | ~70%, 신뢰도 상한 0.9 |
| Layer 2 패턴 테이블 | `Pattern` 시트에 정규식 추가 | 1.0, 우선 적용 |
| Layer 3 교정 학습 | 인박스 교정에서 패턴 생성 | M2 |

Layer 2는 **시트에서 편집한다.** 코드를 고치지 않고 정규식만 추가하면 된다.
패턴을 고친 뒤 `reprocessAll()`을 돌리면 과거 문자가 전부 다시 파싱된다.

## 분류

```
1. Merchant.alwaysAsk        -> 물어봄
2. Merchant.isPassthrough    -> 물어봄 (네이버페이 등 간편결제)
3. Merchant.defaultCategoryId-> 확정
4. Rule (learned)            -> 확정
5. Rule (builtin, contains)  -> 확정
6. 실패                      -> 미분류 -> 알림
```

간편결제는 가맹점이 `네이버파이낸셜` 로 찍혀서 무엇을 샀는지 알 수 없다.
그래서 `isPassthrough`로 표시해 **항상 물어본다.**

같은 가맹점을 **두 번 연속** 같은 카테고리로 고르면 기본 카테고리로 승격한다.
한 번 잘못 고른 것이 영구 고착되는 걸 막으려고 2회로 뒀다.

## 카테고리

```
지출  배달 · 외식(└카페) · 마트 · 편의점 · 교통 · 의료 · 미용
      쇼핑 · 취미 · 구독 · 경조사 · 금융비용 · 기타
수입  급여 (상여 포함)
이체  카드대금 · 저축투자 · 현금인출
태그  여행 · 쇼핑 · 업무 · 회수예정
```

카테고리는 **배타적**, 태그는 **직교**. 여행 중 외식은 카테고리 `외식` + 태그 `여행`.
이렇게 해야 "여행 지출 총액"도 뽑히고 "외식 총액"도 안 망가진다.

`금융비용`은 리볼빙 이자·연회비·송금 수수료. 따로 두면 "돈 쓰는 데 드는 돈"이 보인다.

## 화면 (M3)

```
[홈]       남은 예산 게이지 + 하루 가용액  ← 최상단
           월 수입/지출 → 캘린더(기본 펼침) → 최근 거래
[카테고리]  도넛 + 리스트 + 전월 대비 + 예산 진행률
[인박스]    미분류 / 해석 실패 / 고정지출·구독 / 회수 예정
[더보기]    예산 · 계정 · 분류 규칙 편집 · 앵커 대사 · 내보내기 · 자동화 상태
```

- 캘린더 한 칸은 55pt라 숫자 두 개가 안 들어간다. **지출 1줄 + 수입은 점 하나.**
- 색만으로 수입/지출을 구분하지 않는다. 기호를 함께 쓴다.
- 홈 최상단은 합계가 아니라 **"오늘 쓸 수 있는 돈"** — 행동을 바꾸는 건 이 숫자다.

## 알림

자동 분류 성공 → **알림 없음.** 미분류만 알림.
5분 내 미분류 3건 이상이면 개별 알림 대신 요약 1건으로 묶는다.

단축어에서는 네이티브 알림 액션 버튼을 못 쓴다. 대신 `메뉴에서 선택`이
알림으로 떠서 탭하면 메뉴가 열린다. 1탭 + 1선택.
